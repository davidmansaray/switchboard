# Synthetic scenario recordings

The committed JSON recordings were generated by the deterministic **scripted** desk policy. Northgate Plant & Access Hire, its conversations, booking records and contact details are fictional demo fixtures. These recordings do not demonstrate live model responses or externally delivered email.

Each file name and `key` field are the first 32 hexadecimal characters of a SHA-256 hash of the normalised request. They are lookup checksums, not credentials. The scanner allowlist enumerates only the 73 known checksum values in these committed scripted fixtures. It excludes no file or directory. Prompts, evidence, tool results and any other credential-like values in the same files remain scanned.

`RecordReplayModel` maps recorded identifiers onto the current fixture. Replay falls back to the scripted policy on a miss and counts misses. `EVAL_REQUIRE_RECORDINGS=true pnpm eval:replay` requires fixture coverage.

New live recordings can contain prompts, evidence and tool results from your provider session. Review them separately before adding them to public history. The committed fixtures support a reproducible offline demonstration.

The set combines the original scripted CLI-story recordings with recordings generated from the exact harness eval driver during publication preparation. Both sources are deterministic; the strict gate uses the eval driver. To refresh that coverage offline, run `RECORD_SOURCE=scripted EVAL_LLM_MODE=record pnpm exec vitest run --project evals`, then run the strict replay check.
